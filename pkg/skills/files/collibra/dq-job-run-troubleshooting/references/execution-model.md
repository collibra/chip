# How a Collibra DQ job executes

Source: Collibra docs — About Data Quality & Observability (cloud), About Edge.

## Components
- **Collibra Platform (DQ & Observability)** — UI/APIs where jobs are defined, scheduled and results stored.
- **Edge site** — the only component in the customer's environment. Manages all connections and authentication to data sources. Runs on bundled k3s or a managed Kubernetes cluster. Types:
  - *Standard* (customer-installed): customer owns the cluster, can use the Edge CLI.
  - *Collibra Cloud*: Collibra-managed, auto-upgraded, reaches data sources over the internet; no Edge CLI; some features unavailable.
- **Connection** — JDBC link from an Edge site to a data source (host, auth, driver, properties).
- **Capability** — what runs on a connection. DQ uses the *Data Quality Pushdown Processing* capability (and a Pullup capability). Debug logging for stage logs is enabled on this capability.

## Job types
- **Pushdown** — SQL generated by DQ runs inside the source database. Edge only orchestrates and returns aggregates. Stage logs: Stage 2 (Spark submit).
- **Pullup** — Edge launches Spark on its Kubernetes cluster, reads rows via JDBC, computes checks in Spark. Stage logs: Stage 2 (Spark submit) and Stage 3 (Spark driver).

## Run lifecycle and what each stall means
| Status | What's happening | If it stops/fails here, suspect |
|---|---|---|
| WAITING | Queued in Collibra | Scheduler/concurrency, Edge site not polling |
| DISPATCHED | Sent to Edge | Edge site offline, capability misconfig |
| SETUP | Edge preparing (pods, connection) | K8s scheduling, image pull, connection/auth |
| RUNNING | Query / Spark executing | Permissions, SQL, OOM, timeouts, performance |
| SENDING | Results going back to Collibra | Edge→Collibra network, payload size |
| FINISHED / FAILED / CANCELLED | Terminal | — |

## Where things are configured (who can change them)
- Source query, columns, run-date window, monitors, schedule → the **DQ job** (DQ user; `dq_update_job`).
- Credentials, JDBC properties, driver → the **Edge connection** (Edge admin).
- Spark/K8s sizing, debug logging → the **Edge capability** (Edge admin).
- Node capacity, quotas → the **Kubernetes cluster** (customer platform team; not applicable to Collibra Cloud sites).
- Grants, roles, warehouses, timeouts → the **source system** (DBA).

## Log availability
Stage logs are stored only when Edge debug logging is enabled on the job's capability, and are purged after the platform retention period. Without them, `dq_get_job_run` still returns `exception` and `executedQuery`, which often identify connection/auth/SQL failures.
